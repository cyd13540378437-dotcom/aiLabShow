# Yudi AI Lab 个人产品实验室站点简报 v0.3

域名：`yudi-ailab.com`

v0.3 核心调整：三个项目不强行使用同一种展示方式，而是根据项目性质选择不同证据形态。

## 三类证据形态

### Idea Storm Lab：界面证据

这是三个项目里最适合放真实截图的项目，因为它已经是一个可运行产品，截图能直接证明产品完成度、信息架构和交互流程。

已提供截图可覆盖：

- 灵感墙：团队想法总览、白板感、便利贴式信息组织。
- 分析结果：左侧想法列表 + 右侧结构化分析，体现 LLM 分析不是普通聊天输出。
- 商业画布：将想法转化为价值主张、客户细分、渠道、收入、成本等结构化判断。
- 方向归纳：从多个想法中归纳业务方向，体现“团队决策支持”而不是单点分析。

页面展示建议：

1. 首图使用“灵感墙”截图，直观表现产品气质。
2. 第二张使用“分析结果”截图，说明核心能力。
3. 第三张使用“商业画布”截图，证明分析结构化。
4. 第四张使用“方向归纳”截图，即使是空状态也可以保留，用来说明下一步能力边界。

推荐文案：

> Idea Storm Lab 是一个面向早期创业团队的邀请制脑暴工具。它将成员提交的模糊想法转化为结构化分析、商业模式画布和方向归纳材料，帮助小团队从“有想法”走向“可比较、可讨论、可验证”。

## Design Harness：方法论证据

Design Harness 不一定需要放大量截图。它不是一个普通应用界面，而是一套 AI 设计工程协议和项目记忆系统。强行用截图展示，反而可能让它看起来像“文档仓库”。

更适合展示：

- 一张机制图：Work Item、STATE、Gate、Project Memory、Outputs、VISUAL_DESIGN 的关系。
- 一段设计思想：为什么 AI 设计协作需要状态、记忆、用户批准和封存边界。
- 一个流程摘要：Visual Seed → Reference Selection → Palette / Typography / Exclusions → Prototype → Review → Outputs。
- 一个文件结构局部：只作为辅助，不作为主证据。

页面展示建议：

1. 不做大截图轮播。
2. 使用一张自绘架构图或流程图。
3. 用“设计原则”卡片表达核心思想。
4. 只放 1 张仓库/文档结构小图作为真实性证明。

推荐文案：

> Design Harness 关注的不是让 AI 生成一次性页面，而是让 AI 在产品设计与实现过程中拥有可恢复的上下文、明确的用户确认点、可审计的设计决策和可继承的项目记忆。

核心设计思想：

- Thread 只是临时工作现场，Work Item 才是可验收任务。
- AI 不应静默改写已确认的设计历史。
- 视觉方向、配色、排版、设计禁区和最终关闭都需要用户确认。
- 项目记忆应该沉淀为可读文件，而不是只存在对话上下文里。

## ARCOS Dispatch Runtime Lab：设计思想证据

ARCOS 不建议放真实截图。它更接近企业级复杂业务调度与策略验证，公开展示时应避免暴露客户、内部系统、真实资源、真实工单或业务敏感细节。

更适合展示：

- 抽象后的三层架构：dispatchRuntime / personalWorkRank / domainOptimization。
- 调度目标思想：有限资源下最小化调度域整体违约风险，而不是追求每张工单都不逾期。
- 四象限策略：timePriority × riskRateLevel。
- WHL 环层思想：用工作难度修正权重，避免维度爆炸。
- WG1-WG8 评分组：在岗、位置、负载、经验、效率、稳定、资源属性、技能适配。
- 可解释验证：策略对比、随机基线、SLA、负载均衡、Trace 追踪。

页面展示建议：

1. 不放真实报告截图。
2. 使用一张抽象架构图。
3. 使用一张策略模型图：四象限 + WHL + WG1-WG8。
4. 用一段“产品设计思考”说明为什么调度是风险治理问题。

推荐文案：

> ARCOS Dispatch Runtime Lab 是一次面向企业级工单调度场景的产品设计实验。它将调度问题从“派给谁”拆解为工单风险、资源能力、时间压力、工作难度、负载均衡和可解释验证之间的系统性取舍。

核心设计思想：

- 调度不是追求每张工单都不逾期，而是在资源有限时最小化整体违约风险。
- 单次调度解决“单张工单 → 多个资源”的匹配问题。
- 个人工作队列排序解决“单个资源 → 多张工单”的注意力问题。
- 域级优化解决“多个需求 ↔ 多个资源”的整体资源治理问题。
- 策略必须能解释、能追踪、能仿真、能和随机基线比较。

## 首页三项目呈现方式

首页不再把三个项目做成同款卡片，而是用不同标签说明证据形态：

- Idea Storm Lab：可运行产品 / 界面截图
- Design Harness：方法论系统 / 协议框架
- ARCOS：复杂业务决策 / 策略设计

首页短文案：

> 这三个实验分别覆盖 AI 产品工作的三个阶段：从早期想法生成，到产品设计协作，再到企业级复杂决策。它们共同指向同一个问题：AI 如何进入真实工作流，而不是停留在一次性内容生成。
