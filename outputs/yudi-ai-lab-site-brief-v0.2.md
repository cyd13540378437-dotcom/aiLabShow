## ARCOS 详情页内容

### 项目定位

ARCOS Dispatch Runtime Lab 是一个面向企业级工单调度场景的调度运行时与策略验证沙盒。它围绕 `dispatchAgent` 的微观层 `dispatchRuntime`、中观层 `personalWorkRank` 和宏观层 `domainOptimization` 建立能力分层，并通过仿真、策略对照、评分解释和 HTML 可视化报告验证调度策略是否真的有效。

这个项目不是简单算法 demo，而是把产品策略、业务规则、数据契约、评分权重、资源状态、调度结果和验证报告串成一条闭环。

### 背景问题

企业级调度的本质不是“把每张工单都尽快派出去”，而是在资源有限的情况下，把资源优先分配给最需要保障的工单，从而降低调度域内整体违约风险。

这类场景有几个难点：

- 工单类型不同：计划巡检、应急抢修、用户报事、排查处理等，时效和风险完全不同。
- 资源状态复杂：技能、位置、排班、负载、经验、履约稳定性都会影响派单结果。
- 策略不是单一规则：高时效高风险、低时效高风险、高时效低风险等场景需要不同权重。
- 调度后仍会变化：暂停、延期、位置变化、前置条件变化会影响个人工作队列。
- 决策必须可解释：不能只输出“派给谁”，还要解释为什么这么派、候选资源怎么被过滤和排序。

### 解决方案

ARCOS 将调度策略拆为三层：

- 微观层 `dispatchRuntime`：解决单张工单应该由哪个资源承接，以及初始 `distributeTime` 如何确定。
- 中观层 `personalWorkRank`：解决某个资源已经形成承接关系后，个人工作队列中的工单时间是否需要更新。
- 宏观层 `domainOptimization`：面向多需求与多资源的域级再优化，当前作为后续方向。

第一阶段重点落地 `dispatchRuntime` 与 PWR 仿真：

- A1 工单协议：工单类型、专业、位置、时效、风险等输入。
- B2-B6 资源协议：静态档案、动态状态、履约画像、排班窗口、楼栋空间。
- A3 评估：通过 `timePriority × riskRateLevel` 进入四象限策略。
- WHL 环层：用工作难度修正基础象限，避免维度爆炸。
- WG1-WG8 评分：在岗、位置、负载、经验、效率、稳定、雇佣类型、技能覆盖。
- C2 派单结果：输出主资源、备选资源、调度摘要和追踪信息。

### 策略设计亮点

1. 四象限策略不是拍脑袋，而是基于“时间紧迫度”和“综合风险等级”拆分调度取舍。
2. `workHardLevel` 被设计成环层，不新增象限，从产品管理上控制策略复杂度。
3. WG1-WG8 将资源能力拆成可解释的评分组，避免黑盒排序。
4. 策略文档可以通过 LLM 解析成 `snapshot.json`，让产品策略与运行时权重建立连接。
5. 支持多策略横向对比，包括 default、balanced、random baseline 等。

### 验证与报告

项目输出三类报告：

- 文本报告：批量调度汇总、评估指标、策略对比。
- JSON 报告：供前端或后续分析复用。
- HTML 可视化报告：包含核心指标雷达、WG 加权贡献、Top1 一致性、资源负载、工单下钻等视图。

已有样例报告显示：

- 23 张工单中 22 张成功调度，1 张无可用资源。
- SLA 达成率 100%。
- 策略均分相对随机基线提升约 19.5%。
- PWR 三档对照可以输出提前下发数、重排率、震荡次数、SLA 达标率、负载标准差等指标。
