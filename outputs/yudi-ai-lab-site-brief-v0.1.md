## Design Harness 详情页内容

### 项目定位

Design Harness 是一套给 Codex 使用的 AI 产品设计工程协议。它关注的不是“让 AI 画一个页面”，而是让 AI 在真实产品设计和实现过程中拥有可恢复的上下文、明确的用户确认点、可审计的设计决策和可继承的项目记忆。

### 背景问题

普通 AI 协作很容易出现几个问题：

- 换一个对话后，设计方向、用户批准和验收证据丢失。
- AI 容易把抽象的风格词汇落回通用 SaaS 页面、白底卡片和蓝紫渐变。
- 设计结果缺少状态记录，后续需求可能静默改写历史。
- 交付物、视觉基线和项目长期记忆没有清晰边界。

### 解决方案

Design Harness 把设计任务组织成可独立验收的 Work Item，并通过 `STATE.md`、`REFERENCE_SELECTION.md`、`VISUAL_DESIGN.md`、`project-memory/` 和 `outputs/` 等文件，把设计过程拆成可追踪的生命周期事件。

核心机制：

- Work Item：把任务从临时对话中抽出来，形成可恢复的产品/设计事件。
- Gate：在视觉方向、配色、排版、原型、完成验收等关键节点等待用户确认。
- Project Memory：沉淀业务、产品、UX、视觉、工程和决策基线。
- Outputs：区分当前确认入口与历史事件归档。
- Context-bound Final Review：在关闭前基于本次上下文做最终审查。

### 我的角色

- 定义产品问题和协议边界。
- 设计 Work Item、生命周期状态、Gate 和 Project Memory 机制。
- 编写 PRD、架构说明、兼容安装说明与版本变更文档。
- 用真实项目验证轻量流程、视觉流程、Successor 事件和交付归档。

### 能力体现

- AI Agent 工作流设计。
- 复杂协作流程抽象。
- 产品状态机与生命周期设计。
- Human-in-the-loop 产品机制。
- 设计系统和项目记忆的边界建模。

## Idea Storm Lab 详情页内容

### 项目定位

Idea Storm Lab 是一个面向早期创业团队的邀请制脑暴工具。它用于收集团队成员的创业想法，并通过 LLM 将模糊想法整理成可讨论的结构化分析，帮助小团队从“各自有想法”走向“可以比较、可以讨论、可以验证的业务方向”。

### 背景问题

早期创业团队常见的问题不是没有想法，而是：

- 想法分散在聊天记录、文档和个人脑子里。
- 讨论容易发散，缺少统一分析框架。
- AI 分析如果只是裸提示词，容易套话、乐观和缺少验证动作。
- 多个想法之间难以比较，更难归纳成适合当前团队推进的方向。

### 解决方案

Idea Storm Lab 将流程拆为：

1. 写想法：成员提交标题、内容、图片和文档。
2. 分析结果：系统基于项目内 Skill 生成结构化分析。
3. 灵感墙：团队查看所有成员的想法沉淀。
4. 方向归纳：从多个已有想法中结合团队属性和归纳维度生成方向建议。

核心能力：

- 邀请码注册和登录。
- 成员身份与作者权限。
- 多想法实例管理。
- 图片和文档附件上传。
- LLM 文字分析与商业模式画布。
- 分析章节备注、评价和评论。
- 澄清问题回答后继续分析。
- 方向归纳、版本历史和采纳锁定。

### Skill 设计

Idea Storm Lab 的重点不是简单调用 LLM，而是通过 `skills/analysis_skill.md` 把分析约束成创业产品策划、商业模式、技术选型、投资人视角和验证动作的综合判断。

Skill 优化原则：

- 更具体，少套话。
- 敢指出风险。
- 区分事实和假设。
- 给出 7 天内可验证的动作。
- 竞品不确定时不编造，转为替代行为和调研建议。

### 我的角色

- 定义产品定位、核心流程和信息架构。
- 设计邀请制团队协作、作者权限、灵感墙、分析结果和方向归纳。
- 设计并迭代 LLM 分析 Skill。
- 推动从 v0.1 到 v0.4 的产品功能演进。
- 规划部署、数据存储、长连接、SQLite 并发和服务稳定性。

### 能力体现

- AI 原生产品流程设计。
- 从模糊需求到可运行工具的产品落地。
- LLM Skill 和分析框架设计。
- 团队协作权限与内容流设计。
- 创业想法评估、商业模式和验证动作抽象。
