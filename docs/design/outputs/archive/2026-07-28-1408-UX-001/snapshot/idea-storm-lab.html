01 / Product premise

脑暴不缺输入，缺的是共同判断。

早期团队的想法往往散落在聊天、文档和个人脑海里。Idea Storm Lab 不把 AI 当作一次性答案生成器，而是把每条想法送进同一条协作链：保留原始材料、形成结构化分析、公开给团队讨论，最后在共同条件下归纳方向。

从“我有一个想法”，走到“我们知道接下来验证什么”。

Input

允许想法尚未成型

文字、图片与文档都可以成为起点，先保留语境，再进入分析。

Analysis

把模糊变成可讨论结构

内容提取、竞品、用户、业务流程、商业画布和风险被组织为共同语言。

Decision

让团队条件进入判断

方向归纳同时读取团队属性、归纳维度与多条分析结果，避免只比较点子表面。

02 / Collaboration loop

四个动作，形成一条可返回的链。

这里没有把“提交想法”和“得到 AI 报告”当成终点。每个阶段都保留返回、补充、重新分析和多人查看的入口，让洞察能继续变成选择。

01写下想法 02形成分析 03共享灵感 04归纳方向
Stage 01

写下想法

左侧保持低门槛输入，右侧立即承接分析进度。提交不是离开当前任务，而是让结果在同一工作台展开。

Stage 02

形成分析

分析结果不是一块长文本：文字报告负责推理，商业画布负责对齐关键业务构成，章节备注让团队把判断留在证据旁边。

Stage 03

共享灵感

灵感墙让团队看到彼此的原始想法与分析入口。所有人可以查看，编辑权仍归作者，开放讨论与内容归属被同时保留。

Stage 04

归纳方向

至少选择三条已有分析的想法，再加入团队属性与共同维度。系统比较的不是哪条文字更漂亮，而是哪条方向更适合当前团队推进。

03 / Product system

小型工具，也要有真实产品边界。

Idea Storm Lab 不是只为展示视觉的原型。邀请制身份、作者权限、异步分析、版本记录与本地数据持久化共同构成了一个可以被真实团队反复使用的工作空间。

Identity

邀请制团队空间

注册、登录、口令重置与邀请码控制，让共享发生在有边界的团队语境中。

Ownership

可见不等于可改

团队成员能查看彼此想法，但原始内容的编辑、重分析和关键状态仍由相应作者控制。

Intelligence

Skill 驱动的结构化分析

项目内分析 Skill 定义分析章节与判断方式，LLM 负责执行，并支持澄清后继续分析。

Continuity

可以回来继续的任务

后台分析、方向版本、采纳锁定和快照让长任务不必占住当前会话，也不会丢掉当时的条件。

Python + SQLite + 原生 Web，保持部署和迭代都足够轻。

当前工程采用单体 Python 服务、本地 SQLite、静态前端与可配置的 OpenAI 兼容模型接口。技术选择服务于一个目标：让小团队能以较低成本拥有自己的 AI 脑暴空间。

04 / Method evidence

把方法，放到台面上。

一个 AI 小工具的差异，不只在界面和模型，也在它如何约束判断。这里公开两份工作证据：Idea Storm Lab 实际调用的分析 Skill 节选，以及 DesignHarnessAgent 为本页维护的中文状态记录。

analysis_skill.md / selected

创业想法分析 Skill

公开节选

任务不是夸赞想法，而是把模糊灵感转化为可讨论、可验证、可取舍的结构化判断。

公开原则

  • 先忠实理解输入，再进行推断。
  • 假设必须看起来像假设，而不是结论。
  • 不编造竞品、市场、融资或政策事实。
  • 建议要落到用户、场景、行为、付费或验证动作。

05 / Release path

功能沿着协作链长出来。

四个版本没有追求堆叠菜单，而是逐步补齐同一条路径：先让想法进入系统，再让分析成为方法，让共享成为团队界面，最后让多条想法进入方向判断。

v0.1.0

想法进入团队空间

邀请制身份、多人提交、附件上传、作者编辑权限，以及基础文字分析与商业画布。

v0.2.0

流程成为清晰页面

信息架构收敛为写想法、分析结果与灵感墙，提交后直接进入分析上下文。

v0.3.0

分析变成可迭代 Skill

从裸提示词升级为项目内专家规则，并接入可替换的 OpenAI 兼容模型接口。

v0.4.0

从想法走向方向

加入方向归纳、章节备注、流式进度、版本历史、采纳锁定与团队条件快照。

06 / What it keeps

先允许一个想法不完整，再帮助团队把它变清楚。

Idea Storm Lab 保存的不是一堆 AI 输出，而是从原始念头、共同分析到方向选择的连续上下文。对早期团队来说，这条连续性本身就是产品价值。
